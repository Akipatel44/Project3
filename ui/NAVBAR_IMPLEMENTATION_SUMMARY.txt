HOW IT WORKS:
=============

1. User logs in with a role (SUPER_ADMIN, SUB_ADMIN, USER, or PUBLIC)

2. AuthContext stores: { user: { role: 'SUPER_ADMIN', ... } }

3. Navbar.jsx gets role from useAuth(): const { user } = useAuth()

4. Menu items filtered by: const menuItems = getMenuByRole(user?.role)

5. Only authorized items are rendered to user

6. Unauthorized menu items are hidden from UI

CUSTOMIZING:
============

Add New Menu Item:
1. Edit src/config/menuConfig.js
2. Add to role array: 
   { id: 'unique', label: 'Label', path: '/path', icon: 'IconName' }
3. Make sure icon is imported in Navbar.jsx
4. Create the page and route in App.jsx

Change Menu Items:
1. Edit MENU_CONFIG in menuConfig.js
2. Reorder items as needed
3. Remove items by deleting from array

Add New Role:
1. Add role object to MENU_CONFIG
2. Update backend to return that role
3. Menu will auto-filter

Add Icons:
1. Import from lucide-react
2. Add to iconMap object
3. Use icon name in menuConfig


SECURITY NOTES:
===============

⚠️ CRITICAL:
- This is UI-level role-based access
- Frontend filtering is NOT secure
- Always validate on backend API
- Backend must check user role for every endpoint
- Never trust frontend role checks

Best Practice:
1. Frontend: Hide menu items for UX
2. Backend: Validate every API request
3. Backend: Return 403 if unauthorized
4. Handle API errors on frontend
