  └─ Browsing only
  └─ 4 menu items
  └─ Must login to do more


AUTHORIZATION FLOW:
===================

User Logs In
    ↓
Backend Returns: { user: { role: 'SUPER_ADMIN', ... } }
    ↓
AuthContext Stores: user.role
    ↓
Navbar Receives: user?.role from useAuth()
    ↓
Calls: getMenuByRole('SUPER_ADMIN')
    ↓
Returns: MENU_CONFIG.SUPER_ADMIN array
    ↓
Renders: Only those menu items
    ↓
Other Items: Hidden from UI


MENU FILTERING LOGIC:
=====================

```javascript
// In Navbar.jsx
const menuItems = getMenuByRole(user?.role)

// In menuConfig.js
export function getMenuByRole(role) {
  if (!role) return MENU_CONFIG.PUBLIC
  return MENU_CONFIG[role] || MENU_CONFIG.PUBLIC
}

// Result:
// SUPER_ADMIN → 7 items
// SUB_ADMIN   → 5 items
// USER        → 4 items
// PUBLIC      → 4 items
```


CONDITIONAL RENDERING:
======================

In Navbar component:

```jsx
{menuItems.map((item) => (
  <NavLink
    key={item.id}
    to={item.path}
    className={isActive ? 'active' : 'inactive'}
  >
    <Icon /> {item.label}
  </NavLink>
))}
```

Only items in menuItems array are rendered.
Other items are completely absent from DOM.

IMPORTANT NOTES:
================

1. Frontend menu is for UX only
   - Backend must validate every API call
   - Frontend hiding items is NOT secure

2. Role must come from backend
   - Never set user.role on frontend
   - Always validate server-side

3. Unauthorized pages should:
   - Still redirect/404 on wrong role
   - Backend API must return 403
   - Frontend should handle gracefully

4. Menu is reactive
   - Changes immediately on logout
   - Updates on role change
   - Reflects current user state

5. All Tailwind CSS
   - No custom styling
   - Uses standard utilities
   - Responsive by default
